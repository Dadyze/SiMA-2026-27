Vježba 2 · prezentacija V7

Održavanje mreže i računara

Kad mreža i računari rade, posao administratora je da tako i ostane: dijagnostika kvarova (v2/p1), procjena pouzdanosti (v2/p2), održavanje štampača (v2/p3), zaštita podataka RAID-om (v2/p4), particije i pokretanje sistema (v2/p5) te virtuelne mašine (v2/p6). Diskovi u vježbama su datoteke prikačene kao loop uređaji.

Vježba 2 · Primjer 1 · v2/p1

Dijagnostika LAN mreže i traženje kvara

bashpokretanje
make v2-p1               # tabela Windows i Linux naredbi, shema laba
make v2-p1-lab           # naredbe na ispravnoj mreži (sudo)
make v2-p1-kvar          # slučajan, skriven kvar   (KVAR=1..6 bira određeni)
make v2-p1-dijagnoza     # dijagnostika odozdo prema gore
make v2-p1-rjesenje      # koji je kvar bio i vraćanje ispravnog stanja
make v2-p1-clean

ArhitektonskeŠta želimo uraditi

Problem. Korisnik javlja "nemam interneta, klix.ba ne radi". Isti simptom ima najmanje šest uzroka, od kabla do aplikacije. Administratoru treba sistematičan postupak koji brzo pokaže na kojem sloju je kvar, umjesto nasumičnog restartovanja.

Zahtjevi.

  • sve CLI naredbe sa slajdova (ping, ipconfig, tracert, netstat) i njihovi Linux ekvivalenti na mreži koja stvarno radi,
  • stvarna stanja TCP konekcija (LISTEN, ESTABLISHED, TIME_WAIT) sa slajda o stanjima konekcija,
  • kvarovi na različitim slojevima, koji se mogu ubaciti skriveno (vježba) ili određeno (demonstracija),
  • postupak dijagnostike koji staje na uzroku i kaže šta dalje provjeriti,
  • isti lab se kvari i popravlja više puta bez ponovne izgradnje.
[pc] 192.168.20.50 --- [ruter] 192.168.20.1 / 203.0.113.2 --- [internet] web klix.ba 198.51.100.10:80
                                                                          DNS 198.51.100.53

Arhitektura. Tri namespace-a. Na "internetu" rade pravi servisi: web server i DNS server, pa su odgovori, kodovi grešaka i stanja konekcija stvarni. Kvar je stanje laba, a ne poseban lab: jedna funkcija ga ubacuje, a druga vraća sve u ispravno stanje.

ImplementacijskeKako je napravljeno

DNS je dnsmasq s jednim zapisom (klix.ba), a web server je modul http.server iz Pythona, pokrenut u namespace-u interneta i vezan za adresu servera. Oba se pokreću u pozadini, a njihovi PID-ovi se čuvaju u /run/sima-v2p1.

Stanja konekcija se prave namjerno: exec 3<>/dev/tcp/... je bash-ov način da se otvori TCP konekcija bez dodatnih alata; drži se otvorena 15 s (ESTAB). curl pravi jedan zahtjev; HTTP/1.0 server prvi zatvara konekciju, pa ona na serveru ostaje u stanju TIME-WAIT.

Svaki kvar je jedna naredba koja mijenja tačno jedan dio laba. Prije kvara se uvijek poziva ispravno, pa je u labu u svakom trenutku najviše jedan kvar. Broj kvara se zapisuje u datoteku, a za slučajan kvar se ispisuje samo prijava korisnika.

Dijagnoza je niz provjera po slojevima, od fizičkog prema aplikacijskom: link (LOWER_UP znači da je kabl spojen), loopback i vlastita adresa, gateway pročitan iz tabele usmjeravanja, udaljena IP adresa, DNS i na kraju servis. Svaka provjera je provjeri opis naredba, a || nakon nje ispisuje vjerovatan uzrok i završava funkciju. DNS se smatra ispravnim samo ako dig vrati IPv4 adresu, jer dig i poruku o grešci piše na standardni izlaz.

izlaz make v2-p1-kvar KVAR=3 pa make v2-p1-dijagnoza
   OK   1. link na eth0 (LOWER_UP: kabl je spojen)
   OK   2. loopback i vlastita adresa (ping 127.0.0.1 i ping vlastite IP)
   OK   3. gateway iz tabele usmjeravanja odgovara
   OK   4. udaljeni host po IP adresi (198.51.100.10)
   NE   5. DNS: klix.ba se prevodi u adresu
   Uzrok: DNS (pogrešan ili nedostupan DNS server). IP promet radi, imena ne.

DizajnerskeZašto baš ovako

  • Pravi servisi umjesto simuliranih odgovora: dig, curl i ss pokazuju stvarno ponašanje, uključujući TIME-WAIT, koji se ne može lažirati. Student uči na istim izlazima koje će vidjeti na serveru.
  • Kvar kao stanje i funkcija ispravno čine vježbu ponovljivom: kvar se ubacuje i popravlja sekundama, pa se za jedan termin može uraditi svih šest.
  • Šest kvarova na šest slojeva (kabl, adresa, gateway, ruter, DNS, aplikacija) pokrivaju cijeli put paketa; kvar "servis ne radi" je namjerno uključen jer je mreža tada potpuno ispravna, a korisnik i dalje "nema interneta".
  • Dijagnoza staje na prvom neuspjehu: kad padne niži sloj, padaju i svi viši, pa bi njihov ispis samo zbunjivao. Redoslijed provjera je isti onaj koji se uči na vježbama (OSI model odozdo).
  • Skriven kvar: cilj je vježbati dijagnostiku, a ne čitati rješenje; rješenje je posebna naredba.
Vježba 2 · Primjer 2 · v2/p2

Određivanje pouzdanosti složenih sistema

bashpokretanje
make v2-p2                                          # primjeri s vježbi
python3 v2/p2/pouzdanost.py serijski 0.95 0.9 0.99   # vlastiti račun
python3 v2/p2/pouzdanost.py paralelno 0.97 0.97

ArhitektonskeŠta želimo uraditi

Problem. Iz pouzdanosti komponenti (vjerovatnoća da komponenta radi u periodu, npr. godinu dana) treba izračunati pouzdanost sistema i pokazati zašto se kritične komponente (diskovi, napajanje) udvostručuju. Primjeri s vježbi: RAID 1 od dva diska s pouzdanošću 0.97 i računar od komponenti s pouzdanošću 0.95.

Zahtjevi.

  • serijska veza: sistem radi samo ako rade sve komponente, R = R1 · R2 · ... · Rn,
  • paralelna veza: sistem otkaže samo ako otkažu sve, N = N1 · N2 · ... · Nn, R = 1 - N,
  • kombinovana veza (blok-dijagram pouzdanosti),
  • postupak s međukoracima, kao na tabli, i proizvoljan račun za zadatke.

Arhitektura. Dvije funkcije, serijska i paralelna veza, od kojih se gradi svaki složen sistem: kombinovana veza je samo serijska veza čiji su neki članovi paralelne veze.

ImplementacijskeKako je napravljeno

reduce množi proizvoljan broj članova, pa funkcije rade za n komponenti. Paralelna veza je proizvod nepouzdanosti (1 - x), oduzet od 1.

izlaz make v2-p2 (skraćeno)
   N = N1 * N2 = (1 - 0.97) * (1 - 0.97) = 0.03 * 0.03 = 0.0009
   R = 1 - N = 1 - 0.0009 = 0.9991 = 99.91 %
   R = 0.95 * 0.95 * 0.95 * 0.95 * 0.95 = 0.95^5 = 0.7738 = 77.38 %
   R = 0.9975 * 0.95 * 0.95 * 0.95 * 0.9975 = 0.8531 = 85.31 %

DizajnerskeZašto baš ovako

  • Funkcije kao blokovi dijagrama: kod serijski(paralelno(p, p), p, p, p, paralelno(p, p)) izgleda isto kao blok-dijagram na tabli, pa je prevod s papira u kod direktan.
  • Python bez biblioteka: račun, ne upravljanje sistemom; radi bez root-a i na ispitnom računaru.
  • Treći primjer (redundantno napajanje i RAID 1) povezuje formulu s praksom iz istih vježbi (pitanje: "kako se povećava pouzdanost napajanja servera") i s v2/p4.
  • Pravilo uz rezultat: serijska veza je uvijek manje pouzdana od najslabije komponente, paralelna uvijek pouzdanija od najpouzdanije (pitanje 6 s vježbi).
Vježba 2 · Primjer 3 · v2/p3

Održavanje štampača (CUPS)

bashpokretanje
make v2-p3          # štampači i redovi čekanja (lpstat -t), samo čita
make v2-p3-lab      # mrežni štampač, štampa, zastoji, zaglavljen red (sudo)
make v2-p3-clean

ArhitektonskeŠta želimo uraditi

Problem. Najčešći softverski zastoji štampe sa slajdova: mrežni štampač nedostupan, poslovi se gomilaju u redu, red je zaglavljen. Administrator treba znati instalirati mrežni štampač, pratiti red i otkloniti zastoj bez restartovanja svega.

Zahtjevi.

  • pravi servis za štampu (CUPS) s pravim redom čekanja,
  • "mrežni štampač" koji se može isključiti i uključiti, da se vidi ponašanje kad je nedostupan,
  • bez papira i bez stvarnog štampača, a sadržaj odštampanog posla da se može pročitati.
lp  -->  CUPS red "sima-stampac"  --(socket://127.0.0.1:9100, RAW/JetDirect)-->  emulator_stampaca.py  -->  posao-NNN.txt

Arhitektura. CUPS je servis računara, a štampač je emulator: mali TCP server na portu 9100, istom portu na kojem slušaju mrežni štampači (RAW/JetDirect). Emulator radi na 127.0.0.1, ne u namespace-u, jer bi inače CUPS trebao mrežnu vezu prema labu, što bi promijenilo mrežu računara.

ImplementacijskeKako je napravljeno

Emulator prihvata konekciju, čita sve dok druga strana ne zatvori vezu (tako izgleda RAW štampa) i zapisuje posao. Posao se imenuje po broju postojećih datoteka, pa ponovno pokretanje emulatora ne prepisuje ranije poslove.

-E omogućava red i odmah ga pušta u rad, -v je adresa uređaja, -m raw red bez drajvera (posao ide nepromijenjen), a -L i -D su lokacija i opis koji se vide u lpstat -l.

DizajnerskeZašto baš ovako

  • Emulator umjesto PDF štampača: virtuelni PDF štampač nikad nije nedostupan, a zastoj "štampač nedostupan" je glavna tema. Emulator se gasi i pali kao pravi uređaj, a CUPS se ponaša isto kao prema pravom štampaču (ponovni pokušaji, poruka u lpstat -l).
  • Port 9100 povezuje lab sa slajdom: mrežni štampač je uređaj s IP adresom i portom, a dijagnostika je ista kao za svaki mrežni servis (ping, provjera porta).
  • RAW red: nema drajvera ni filtera koji bi mogli biti uzrok greške u vježbi; upozorenje CUPS-a o zastarjelim RAW redovima je objašnjeno u ispisu, a za pravi štampač se navodi -m everywhere.
  • Čekanje sa vremenskim ograničenjem (cekaj_red) umjesto fiksnog sleep: CUPS ponovno šalje posao u intervalima, pa vježba čeka tačno onoliko koliko treba.
  • Dijeljenje se samo prikazuje: cupsctl --share-printers bi promijenio postavke CUPS-a računara za cijelu mrežu.
Vježba 2 · Primjer 4 · v2/p4

Softverski RAID 1 (ogledalo)

bashpokretanje
make v2-p4                                   # postojeći RAID nizovi i diskovi, samo čita
make v2-p4-lab                               # RAID 1, kvar diska, zamjena, obnova (sudo)
sudo RAID_ALAT=btrfs bash v2/p4/raid1.sh vjezba   # ista vježba s btrfs RAID 1
make v2-p4-clean

ArhitektonskeŠta želimo uraditi

Problem. Disk je komponenta koja najčešće otkazuje, a nosi podatke. Prezentacija pokazuje RAID 1 u BIOS-u i u Windows Disk Managementu. Na Linuxu treba pokazati da ogledalo omogućava rad bez jednog diska, kako se pokvaren disk mijenja bez gubitka podataka i šta RAID ne rješava.

Zahtjevi.

  • pravi RAID 1 nad pravim blok uređajima, bez rizika za diskove računara,
  • dokaz ispravnosti podataka nakon svakog koraka (ne samo "datoteka postoji"),
  • kvar, rad u degradiranom stanju, zamjena i obnova,
  • da radi i na jezgrama bez md modula (dio WSL2 jezgri).
/var/tmp/sima-v2p4/disk1.img -> /dev/loopA --\
                                               RAID 1 -> /mnt/sima-raid   (ext4 na /dev/md/sima-raid1, ili btrfs)
/var/tmp/sima-v2p4/disk2.img -> /dev/loopB --/
/var/tmp/sima-v2p4/disk3.img -> /dev/loopC     rezervni disk za zamjenu

Arhitektura. Tri datoteke od 256 MB su diskovi (loop uređaji); jezgra ih vidi kao prave blok uređaje. Ista vježba ima dvije implementacije: mdadm (klasični Linux software RAID, ekvivalent Mirrored Volume) i btrfs RAID 1, a skripta bira onu koju jezgra podržava.

ImplementacijskeKako je napravljeno

mdadm --run preskače interaktivno pitanje, a --wait čeka kraj početne sinhronizacije. Kod btrfs-a -d raid1 -m raid1 znači da su i podaci i metapodaci u ogledalu.

Kod mdadm-a se kvar označava (--fail), pa disk uklanja i dodaje novi; obnova je automatska. Kod btrfs-a se disk stvarno "vadi" (otkači loop uređaj), pa sistem odbija obično montiranje dok se izričito ne traži -o degraded. Zamjena je btrfs replace po broju nestalog diska, a balance u ogledalo vraća blokove upisane za vrijeme kvara (oni su upisani bez kopije).

DizajnerskeZašto baš ovako

  • Loop uređaji ispunjavaju zahtjev "pravi blok uređaji bez rizika": mdadm i btrfs ne razlikuju loop od SATA diska, a greška u vježbi pogađa samo datoteke u /var/tmp.
  • Dvije implementacije istih koraka umjesto vježbe koja kod dijela studenata ne radi: izbor alata je jedna funkcija, a koraci (ogledalo, kvar, degradiran rad, zamjena) su isti, pa je pouka ista.
  • Kontrolni zbir (sha256) umjesto ls: dokaz da su podaci bit po bit isti nakon kvara i obnove.
  • Upis za vrijeme kvara pokazuje da sistem nastavlja raditi i objašnjava zašto je kod btrfs-a poslije potreban balance.
  • "RAID nije backup" kao zadnji korak: najčešća zabluda, pokazana jednom naredbom rm.
  • Čišćenje briše i tragove (--zero-superblock, btrfs device scan --forget), pa ponovna vježba uvijek kreće od nule.
NapomenaVarijanta s btrfs-om je izvršena u razvojnom okruženju; varijanta s mdadm-om nije, jer razvojna jezgra nema md modul.
Vježba 2 · Primjer 5 · v2/p5

Particije diska (MBR i GPT), UUID, fstab i boot opcije

bashpokretanje
make v2-p5          # diskovi, MBR/GPT, UEFI/BIOS, boot opcije i fstab ovog računara, samo čita
make v2-p5-lab      # MBR, GPT, datotečni sistemi, UUID i fstab na disku-datoteci (sudo)
make v2-p5-clean

ArhitektonskeŠta želimo uraditi

Problem. Instalacija i održavanje klijentskog računara traže razumijevanje tabele particija, posebnih particija (System Reserved/EFI, recovery), datotečnih sistema i toga kako sistem zna šta montirati pri pokretanju. Greška u bilo čemu znači računar koji se ne podiže.

Zahtjevi.

  • MBR s primarnim, proširenom i logičkim particijama (ograničenje od 4 primarne),
  • GPT raspored UEFI računara: EFI, sistem, podaci, recovery,
  • datotečni sistemi, UUID i /etc/fstab,
  • bootabilni USB, ali bez rizika da se izbriše pogrešan disk.

Arhitektura. Jedan prazan disk od 1 GB (datoteka na loop uređaju s particijama, losetup -P). Na njemu se pravi prvo MBR, a zatim, nakon brisanja, GPT, pa se razlike vide na istom ispisu fdisk -l.

ImplementacijskeKako je napravljeno

Raspored particija je deklarativna skripta za sfdisk: tip tabele (label), pa po jedna linija za particiju (veličina, tip, ime). Tipovi su skraćenice: 83 Linux, 82 swap, 5 proširena (MBR); U EFI System i L Linux filesystem (GPT). Particija bez veličine zauzima ostatak diska.

DizajnerskeZašto baš ovako

  • Disk-datoteka: isti alati i isti rezultat kao na pravom disku, a diskovi računara nisu u opasnosti; isto načelo kao u v2/p4.
  • Raspored kao skripta, prikazan prije primjene: isti raspored se može ponoviti na mnogo računara (masovna instalacija), a student vidi šta će se desiti prije nego što se desi.
  • MBR pa GPT na istom disku (wipefs između): poređenje bez druge varijable.
  • fstab iz stvarnih UUID-ova: pokazuje zašto se ne koristi /dev/sdX (ime se mijenja kad se doda disk).
  • Bootabilni USB se ne izvršava: dd na pogrešan uređaj briše disk; zato se samo prikazuje, uz upozorenje o razlici sdX i sdX1.
  • partx -u poslije sfdisk: bez udev-a (kontejneri, dio WSL okruženja) jezgra ne napravi odmah čvorove particija; jedna funkcija čini vježbu prenosivom.
Vježba 2 · Primjer 6 · v2/p6

Instaliranje virtuelne mašine (KVM/libvirt umjesto Hyper-V Managera)

bashpokretanje
make v2-p6           # preduslovi i plan, ništa se ne pravi
make v2-p6-up        # Ubuntu slika (~600 MB, jednom), VM, čekanje na IP (sudo, KVM)
make v2-p6-status    # stanje i naredbe za upravljanje
make v2-p6-clean     # SVE=1 briše i preuzetu sliku

ArhitektonskeŠta želimo uraditi

Problem. Procedura sa slajda (Hyper-V Manager, devet koraka: medij, ime, RAM, mrežni adapter, disk, pokretanje, instalacija) treba se uraditi na Linuxu, i to ponovljivo, jednom naredbom, a ne klikanjem kroz čarobnjak.

Zahtjevi.

  • svaki korak sa slajda ima svoj ekvivalent (RAM 1024 MB, mrežni adapter, novi disk, pokretanje),
  • instalacija bez interaktivnog rada, da je može uraditi cijela grupa,
  • plan i provjera preduslova i na računaru bez virtualizacije,
  • upravljanje VM-om (start, gašenje, kontrolna tačka).
Hyper-V korakLinux
instalacijski medij / ISOUbuntu cloud slika (za ISO: virt-install --cdrom)
New Virtual Machine, imevirt-install --name sima-vm
RAM 1024 MB / mrežni adapter--memory 1024 / --network network=default
novi virtuelni diskqemu-img create -f qcow2 -b osnovna-slika ... 10G
interaktivna instalacijacloud-init pri prvom pokretanju
Checkpointvirsh snapshot-create-as

Arhitektura. KVM/QEMU hipervizor kojim upravlja libvirt (qemu:///system), NAT mreža default, disk VM-a kao qcow2 sloj iznad jednom preuzete osnovne slike, a podešavanje sistema (korisnik i SSH ključ) radi cloud-init.

ImplementacijskeKako je napravljeno

SSH ključ se uzima od korisnika koji je pozvao sudo (SUDO_USER), ne od root-a, pa se student kasnije prijavljuje svojim ključem. IP adresa se čita iz DHCP zakupa libvirt mreže (virsh domifaddr).

DizajnerskeZašto baš ovako

  • Cloud slika i cloud-init ispunjavaju zahtjev "bez interaktivnog rada": VM je spremna za oko minutu umjesto dvadesetak minuta instalacije.
  • qcow2 sloj iznad osnovne slike: disk VM-a čuva samo razlike, slika se preuzima jednom, a brisanje VM-a ne briše preuzetu sliku.
  • libvirt i mreža default: isti stek koristi virt-manager, grafički alat sličan Hyper-V Manageru, pa student može nastaviti i iz GUI-ja.
  • Osnovni cilj samo planira: provjera preduslova radi i bez KVM-a, a pravljenje VM-a je opcionalan korak.
  • Tip OS-a s rezervom (generic): starije osinfo baze ne znaju za Ubuntu 24.04, pa bi virt-install odbio pokretanje.
NapomenaPravljenje VM-a traži /dev/kvm (u WSL2 ugniježđenu virtualizaciju). v2-p6-up nije pokretan u razvojnom okruženju; v2-p6 jeste.
